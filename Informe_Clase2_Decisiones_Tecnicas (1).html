1. Decisión de lenguaje de programación

Lenguaje principal: Python

Lenguaje secundario: JavaScript

Justificación técnica:
Se implementa una arquitectura desacoplada Full-Stack defensiva: Python opera en el Backend administrando los sockets señuelo multihilo, la ejecución controlada de netsh en Windows Firewall y las capturas forenses con TShark. JavaScript compone el Frontend en el navegador, consumiendo eventos en tiempo real mediante WebSockets y ofreciendo un Dashboard visual interactivo para la gestión de intrusiones, desbloqueo de IPs y descarga de archivos .pcap, dando estricto cumplimiento a los requisitos RF-04 y RF-05 de la Clase 1.

Librerías clave:
socket, threading, fastapi / flask, subprocess, ipaddress, json, JavaScript WebSockets API / Fetch API.

Riesgos identificados:
Saturación en el canal WebSocket: Ante escaneos masivos de Nmap, la mitigación en el Firewall de Windows se ejecuta de manera prioritaria en Python a nivel de sistema antes de despachar el evento al navegador, asegurando el bloqueo en milisegundos.

Prevención XSS en la interfaz: Toda IP y dato proveniente de la red se sanitiza en JavaScript antes de insertarse en el DOM (OWASP ASVS Control V5.3).

2. Decisión de agente de IA para el desarrollo

¿Usarán agente de IA?: Sí

Agente elegido: Ollama

Justificación:
Seleccionamos Ollama porque ejecuta modelos de lenguaje localmente en la máquina del equipo a costo cero (sin suscripciones a la nube como Google AI Ultra). Esto garantiza total privacidad de las reglas de cortafuegos y el código defensivo, además de permitir asistencia de programación en entornos de red y laboratorios cerrados sin depender de conexión a internet.

¿Requiere conexión a internet?: No, es local

Modelo(s): Qwen2.5-Coder (7B) o DeepSeek-Coder (6.7B)

4. Flujo principal de datos

Un atacante lanza un escaneo de reconocimiento con Nmap (nmap -sS -p-) hacia la máquina Windows → El Módulo de Trampas detecta el intento de conexión en un puerto señuelo (ej. 21 o 2222), extrae la IP atacante y cierra el socket de inmediato → El evento pasa a la cola del Motor de Análisis, que valida la sintaxis de la IP con ipaddress y comprueba la lista blanca (Gateway/DNS) para prevenir DoS por spoofing → Confirmada la intrusión, el motor activa dos acciones simultáneas: 1) El Módulo de Mitigación ejecuta netsh advfirewall insertando la regla de bloqueo inmediato (action=block), cortando el tráfico hostil en milisegundos; 2) El Recolector Forense dispara tshark.exe en segundo plano para generar el volcado evidencia__.pcap → Finalmente, el backend emite el evento vía WebSocket hacia el Dashboard en el navegador, donde JavaScript dibuja la alerta visual en la tabla en tiempo real, emite una notificación emergente del sistema y activa los botones de control para desbloquear la IP o abrir el análisis en Wireshark.
